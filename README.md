# TAGOPA

**광역버스 승차 여유 예측 서비스**

**[서비스 바로가기 → https://hansol000808.github.io/tagopa/](https://hansol000808.github.io/tagopa/)**

버스가 언제 오는지는 알 수 있어도, 내가 탈 수 있을 만큼 자리가 남아 있을지는 알기 어렵습니다. TAGOPA는 공식 실시간 도착정보와 과거 운행 기록을 함께 활용해 지금 다가오는 버스를 확인하고, 정류장과 시간대별 **예상 승차 여유**를 비교할 수 있도록 돕는 웹 서비스입니다.

## 프로젝트 소개

**해결하려는 문제**
동탄에서 서울로 오가는 광역버스는 혼잡한 시간대에 만차가 이어지곤 합니다. 기존 도착정보 앱은 버스가 몇 분 뒤에 오는지, 지금 몇 석이 비어 있는지는 알려 주지만, 내가 기다리는 정류장에서 자리가 남을지, 앞 정류장으로 이동하는 편이 나을지는 판단하기 어렵습니다.

**서비스 목표**
정류장과 요일, 운행 시각별로 과거 기록에서 계산한 승차 여유를 한눈에 비교하고, 실시간 도착정보를 옆에 두어 이용자가 스스로 판단할 수 있게 합니다. 어느 버스나 정류장을 타라고 추천하지는 않습니다.

| 구분 | 내용 |
|---|---|
| 이용 대상 | 동탄과 서울을 광역버스로 오가는 이용자 |
| 대상 노선 | M4130, M4137 (동탄→서울, 서울→동탄 양방향) |
| 기존 도착정보와의 차이 | 도착 시간·현재 빈자리에 더해, 정류장·시간대별 승차 여유의 과거 경향을 함께 제공 |

## 주요 기능

### A. 실시간 버스 도착정보 조회
- 노선, 방향, 정류장을 고르면 **첫 번째·두 번째 버스**의 예상 도착 시간을 보여 줍니다.
- 조회 시점의 **현재 빈자리**, 몇 정류장 전인지, 차종(제공되는 경우)을 함께 표시합니다.
- 각 버스의 예상 도착시각에 가장 가까운 **과거 대표편**을 찾아 **예상 승차 여유**를 함께 보여 주고, "시간표에서 보기"로 해당 칸으로 이동할 수 있습니다. 해당 요일의 과거 기록이 없으면 그렇게 표시합니다.
- 경기도 공식 버스도착정보 API를 이용자가 입력한 인증키로 직접 호출합니다. 정류장을 바꾸거나 새로고침을 누르면 조회하고, 화면이 열려 있는 동안에는 1분마다 자동으로 갱신합니다(탭이 숨겨지거나 10분 이상 조작이 없으면 멈춥니다).
- 도착 예정 버스가 없거나 빈자리 정보가 없을 때는 그 상태를 그대로 표시합니다.

### B. 요일별 예상 승차 여유 비교
- **정류장 × 대표 운행편** 시간표에서 칸마다 대표 시각과 예상 승차 여유(명)를 확인합니다.
- 월~금, 토, 일·공휴일을 따로 집계하며, 칸마다 네 가지 상태로 분류합니다.

| 상태 | 의미 |
|---|---|
| 빠듯해요 | 탈 자리가 적고, 사람들이 타면 거의 다 차는 편 |
| 북적여요 | 탈 자리는 넉넉해도, 사람들이 타면 거의 다 차는 편 |
| 조금 남아요 | 탈 자리는 적지만, 사람들이 타고도 조금 남는 편 |
| 여유로워요 | 탈 자리가 넉넉하고, 사람들이 타고도 남는 편 |

- 칸을 누르면 참고한 기록의 날짜 수, 기준 차종, 계산 근거를 볼 수 있습니다.

### C. 예시 보기
- **출근·퇴근 시간대의 가상 도착 시나리오**로 서비스 흐름을 확인합니다.
- 인증키 없이 이용할 수 있고, 카드에서 "시간표에서 보기"를 누르면 해당 시각의 시간표 칸으로 이동합니다.
- 예시의 도착정보는 실제 실시간 정보가 아닙니다.

## 사용 방법

1. 웹사이트에 접속합니다. 인증키가 없으면 **예시 보기**로 시작하고, 이 브라우저에 인증키를 기억해 둔 경우에는 **실시간 조회**가 먼저 열립니다.
2. 노선과 방향을 고르고, 노선도 목록에서 내 정류장을 선택합니다.
3. 실시간 조회를 쓰려면 설정·안내에서 인증키를 입력한 뒤 "실시간 조회"를 선택합니다. 인증키 없이도 "예시 보기"로 둘러볼 수 있습니다.
4. 아래 시간표에서 요일을 고르고, 칸을 눌러 상세 근거를 확인합니다.

**인증키 안내**
- 공공데이터포털에서 "경기도_버스도착정보 조회" 서비스를 신청해 발급받은 **Decoding(원본키)** 이 필요합니다.
- 키는 이용자가 직접 입력합니다. TAGOPA에는 서버가 없고 키는 이 저장소에도 포함되지 않습니다.
- 기본은 열려 있는 페이지의 메모리에서만 사용합니다. 이용자가 "이 브라우저에 기억하기"를 직접 선택한 경우에만 브라우저의 localStorage에 저장하며, 삭제 버튼을 제공합니다. localStorage는 편의 기능일 뿐 안전한 비밀 저장소가 아닙니다.
- 실시간 조회 시 키는 브라우저에서 공식 API(apis.data.go.kr)로 전송됩니다.

## 데이터 활용과 예상 승차 여유 계산

**사용한 자료**
- 경기버스정보(GBIS)의 과거 도착정보와 잔여석 기록 (2026-09-24 ~ 10-10, 달력상 17일 범위이며 요일마다 기록 일수가 다릅니다): 정류장 도착 시와 승하차 후의 빈자리
- 경기도 광역버스 승하차 인원 공공데이터(2025년 10월): 정류장·시간대별 하차 인원 추정과 일부 승차 인원 보완에 활용
- 운수회사 배차표: 대표 운행편과 차종(정원) 대응의 참고 자료

**계산의 기본 개념**

| 기호 | 의미 |
|---|---|
| V | 정류장에 도착했을 때의 빈자리 (과거 잔여석 기록) |
| A | 예상 하차 인원 (아래 설명) |
| R | 승차 전 여유 = V + A. 시간표 칸의 숫자 |
| F | 승차 후 남는 자리. 같은 운행의 출발 후 기록 또는 다음 정류장 도착 기록 |
| 예상 승차 | R − F |

- **하차 인원(A)**: 2025년 10월의 같은 정류장·같은 시간대 하차 인원 평균(평일 또는 일요일·공휴일 기준)을 그 시간대에 최근 기록상 하루 평균 몇 대가 지나갔는지로 나눈 값입니다. 시간대 합계를 지나가는 운행편에 똑같이 나눠 준 **추정·분배값**입니다.
- **승차 인원**은 보통 R − F로 정해지므로 별도의 승차 통계를 쓰지 않습니다. 다만 다음 정류장 기록이 없어 F를 얻지 못한 경우에만, 같은 방식으로 나눈 2025년 10월의 승차 인원 참고값으로 F를 합성하며 상세 화면에서 구분해 보여 줍니다.
- 새로 시작하는 운행(동탄 기점 등)은 빈 차로 시작한다고 가정하여 R을 차량 정원으로 둡니다.
- 승하차 인원은 개별 운행의 측정값이 아닙니다. 실제 승하차를 복원한 것이 아닙니다.

**네 가지 상태 분류**
색상은 인원 구간 하나로 나눈 것이 아니라 **R과 F를 함께 봅니다.** 같은 요일·같은 대표 운행편·같은 정류장에서 **R과 F를 모두 얻은 기록만** 모아 계산합니다.

- R의 중앙값이 10명 미만이면 "승차 전 여유 적음", 이상이면 "많음"
- 이 기록 중 F가 4석 이하인 기록의 비율이 1/3 이상이면 "승차 후 소진 쪽", 아니면 "남는 쪽"
- 이 둘을 조합한 2×2 분류가 위의 네 가지 상태입니다.
- F가 없는 기록은 비율 계산에서 제외하고, R과 F를 모두 얻을 수 없는 칸은 색을 붙이지 않고 이유를 표시합니다. 기록이 1~2건뿐이어도 분류하되 사용한 날짜 수를 상세에 함께 보여 줍니다.

기준값(10명, 4석, 1/3)은 첫 구현을 위해 정한 값이며, 검증된 최적 기준이나 실제 탑승 확률이 아닙니다. 계산은 집계·중앙값·비율로 이루어진 단순한 규칙이며 학습 모델이나 AI 예측은 사용하지 않았습니다.

**개발 과정에서 다룬 문제**
- 서로 다른 출처(과거 도착 기록, 승하차 집계, 배차표)를 노선·정류장·요일·운행편 기준으로 대응
- 정규편과 출퇴근 전세편을 구분하고, 전세편의 편도 영업 범위를 반영
- 일반 버스(45석)와 2층 버스(70석)의 정원 차이 반영
- 관측 기록과 추정·보완값을 구분해 표시 (보완값에는 ＋ 표식)
- 자정을 넘는 운행을 날짜가 아니라 운행일 기준으로 집계
- 같은 배차 예정편의 날짜별 기록을 시각 차이만으로 나누지 않고 배차표와 차량 기록으로 한 대표 운행편에 묶기(일·공휴일 포함), 한 운행이 두 키로 중복 저장된 기록 정리

## 기술 스택과 구현 구조

| 기술 | 사용 이유 |
|---|---|
| HTML / CSS / JavaScript | 프레임워크 없이 구현한 정적 웹. 별도 빌드 없이 브라우저에서 바로 동작 |
| 경기도 버스도착정보 API | 공식 실시간 도착·빈자리 정보. 서버 없이 브라우저에서 직접 호출 |
| JSON 정적 데이터 | 과거 집계 결과를 노선·요일·운행편별 파일로 나누어 필요한 조각만 불러옴 |
| GitHub Pages | 서버 없이 무료로 공개하고 계산과 화면 처리는 이용자 브라우저에서 수행 |
| Python | 자료 전처리·분석, 그리고 공개용 JSON과 이 저장소의 파일 생성 (스크립트는 개발 원본에 있음) |

```
GitHub Pages ──(정적 웹 + 집계 JSON)──────────────▶ 브라우저
브라우저 ──(이용자 인증키로 직접 조회)────────────▶ 경기도 버스도착정보 API
Python (개발 과정) ─ 과거 자료 분석 → 공개용 JSON 생성 ─▶ GitHub Pages
```

이 저장소(`tagopa`)에는 **화면에 필요한 공개용 정적 파일**(`index.html`, `app.js`, `style.css`, `data/app/recent/`의 집계 JSON)만 있습니다. 원본 수집 기록, 배차표, 분석 스크립트 전체는 포함되어 있지 않으며, 이 파일들은 개발 원본에서 허용 목록 방식의 스크립트로 생성됩니다.

## 데이터 출처와 한계

**출처**
- [공공데이터포털](https://www.data.go.kr/) — 경기도 광역버스 승하차 인원 데이터(2025년 10월분)
- [경기도_버스도착정보 조회](https://www.data.go.kr/data/15080346/openapi.do) (공공데이터포털, 실시간 조회)
- [경기버스정보(GBIS)](https://www.gbis.go.kr/) 과거 도착정보를 가공한 자료
- 운수회사 배차표를 노선·차종 대응에 참고한 자료

**한계**
- 예상 승차 여유는 **과거 자료에 기반한 통계적 추정**이며 실제 탑승 가능 여부를 보장하지 않습니다.
- 실시간 **현재 빈자리**와 시간표의 **예상 승차 여유**는 서로 다른 값입니다. 실시간 버스의 예상 도착시각에 가장 가까운 과거 대표편을 통계적 참고자료로 연결합니다. 이는 동일한 실제 차량이나 운행편으로 확정한 결과가 아닙니다.
- 요일별 기록이 월 1일, 화 2일, 수 2일, 목 2일, 금 1일, 토 1일, 일·공휴일 8일로 적어 대표성과 정확도에 한계가 있습니다. 토요일은 공휴일이 아닌 토요일(2026-10-10) 하루의 기록이며, 추석·개천절 연휴와 한글날을 포함한 일·공휴일 집계는 날짜마다 실제 배차가 같았다는 확인이 아니라 일요일·공휴일을 묶은 통합 집계 방식입니다.
- 같은 배차 예정편에 날짜에 따라 다른 차종의 버스가 투입된 경우(예: 2층 기준 열의 45석 운행일), 그 날짜의 기록은 2층 기준 열의 인원·색과 대표 시각에서 제외하고 상세 화면에 표시합니다. 번호판 일치 여부 등은 시각 연결에서 나온 간접 추정이며 확정이 아닙니다.
- 예시 보기의 도착정보는 가상 시나리오입니다.
- GBIS 과거 도착정보와 배차표를 가공한 자료의 **공개 이용 조건은 아직 완전히 확인하지 못했습니다.**

TAGOPA는 비상업적인 학업·포트폴리오 프로젝트이며, 자료 제공기관이 이 서비스를 승인하거나 예측 결과를 보증한 것이 아닙니다.
